# CiteDock 引用坞

**你记得内容，只是忘了它在哪个文件里。**

CiteDock 不搜文件名，搜正文。设定集、访谈纪要、会议记录、代码注释——只要那句话在文件里，
就能把它连同文件一起捞出来：复制路径、复制 `@` 引用，或把多份正文合并成一份。
**全程离线，源文件全程只读。**

> **English** — CiteDock doesn't search filenames, it searches file bodies. Design docs,
> meeting minutes, code comments — if the sentence is in a file, CiteDock pulls the file out
> with it: copy paths, `@` citations, or merge bodies into one text.
> **Fully offline, read-only on your files, nothing ever uploaded.**
一键复制路径、`@` 引用，或把多份文档**合并成一份**。**全程离线，源文件全程只读。**


|            |                                                          |
| ---------- | -------------------------------------------------------- |
| **平台**     | **仅 Windows**（全局热键与选区探测依赖 Win32 API）                     |
| **Python** | **3.10 或更高**                                             |
| **依赖**     | `PySide6`（必需）；`python-docx` / `pypdf`（可选，缺失时正文退化成只索引文件名） |

## 安装与启动

**1. 装 Python 3.10+**（<https://www.python.org/downloads/windows/>，安装时勾选 *Add to PATH*）

**2. 装依赖**（在 `cite-dock` 目录下）：

```bat
python -m pip install -r requirements.txt
```

**3. 启动**：

```bat
:: 双击即可
start-citedock.bat

:: 或者用命令行（带控制台，方便看报错）
python run.py
```

`start-citedock.bat` 找不到 Python 或缺少依赖时会**停下来把原因讲清楚**，不会闪退。
  
如果你的 Python 不在 PATH 上，二选一：

- 在 `cite-dock` 目录建一个 `.python-path` 文件，里面只写解释器的完整路径
- 或者设一个环境变量 `CITEDOCK_PYTHON` 指向它

**4. 首次使用**：启动后悬浮条停在屏幕下方。点 **设置 → 添加目录** 选出你要索引的文件夹，
  
保存后自动建索引。之后按热键 `Ctrl+Alt+Space`（可在设置里改）随时唤出。

托盘图标（右下角）有：显示/隐藏、设置、重建索引、退出。悬浮条上右键也有同样的菜单。

## 界面与操作

```
┌─────────── 悬浮条（收起态，700×54）───────────┐
│ ⣿ [ 关键词输入……………… ] 取词 常驻 设置 收起 │
└───────────────────────────────────────────────┘
```

| 元素     | 作用                                    |
| ------ | ------------------------------------- |
| `⣿`    | 按住即可拖动整条坞；双击切换常驻                      |
| 输入框    | 输入即搜（220ms 防抖）；`Enter` 立即搜，`Esc` 收起   |
| **取词** | 读剪贴板 → 自动抽 3 个关键词并检索（开会/聊天时先复制一段话最省事） |
| **常驻** | 开启 = 置顶且失焦不隐藏；关闭 = 点别处自动收起，用完即走       |
| **设置** | 检索范围、排除规则、热键、主题、界面语言                       |
| **收起** | 先收结果面板，再收整条坞                          |

有命中时结果面板自动展开，每行可勾选：

| 按钮          | 复制内容                                        |
| ----------- | ------------------------------------------- |
| **复制路径**    | 每行一个绝对路径                                    |
| **复制引用**    | 每行一个 `@路径`（含空格自动加引号），适合粘进支持 @ 引用的编辑器                |
| **复制内容**    | 拼接所选文件的正文，带 `===== 路径 =====` 分隔，总量上限 20 万字符 |
| **打开 / 定位** | 打开文件 / 在资源管理器里选中                            |

双击某一行 = 打开该文件。

界面语言默认跟随系统；在设置里可切换 中文 / English，改完立即生效，无需重启。

## 安全设计

| 约束       | 实现                                                                        |
| -------- | ------------------------------------------------------------------------- |
| 检索范围由你决定 | 只有检索范围（`scopes`）里的目录会被扫描；路径 `realpath` 不在范围内直接丢弃（`app/core/safeguard.py`） |
| 源文件只读    | 所有源文件统一走 `Guard.open_source()`，内部写死 `r`/`rb`；传写模式会直接抛异常                   |
| 写入永不覆盖   | `Guard.free_path()` 遇到同名目标会自动加时间戳后缀，不会 `rm` 后重建                           |
| 无需联网     | 全流程零网络调用；设置里可开 **离线断言**，启动即把本进程 socket 出口堵死                               |
| 可回溯      | 审计日志记录每次索引/写入的来源与统计（`%LOCALAPPDATA%\CiteDock\audit.log`）                  |
| 不污染用户目录  | 索引库与配置都在 `%LOCALAPPDATA%\CiteDock\`，可用环境变量 `CITEDOCK_HOME` 改              |

## 中文检索是怎么做的

SQLite 自带的 `unicode61` 分词器不切中文，`trigram` 分词器又要求查询词至少 3 个字符  
（"简历" 这种 2 字词会直接搜不到）。这里的方案是：

- **入库**：给每个中日韩字符两侧补空格，让 `unicode61` 按"单字"建索引；换行换成一个可见的 `·` 分隔符。
- **查询**：对输入做同样的变换，再包成短语查询——`迷宫生成` 变成 `迷 宫 生 成` 的相邻短语匹配，  
  语义上等价于子串匹配，且不受词长限制、不需要 jieba。
- **排序**：FTS5 `bm25`（文件名权重 ×4）+ 30 天半衰期的"越新越靠前"加权。
- **兜底**：先按"全部关键词都命中"检索，一条都没有时自动放宽成"命中任一关键词"，并在状态栏如实说明。

## 选区探测是怎么做的

开「鼠标取词」后，CiteDock 会装一个全局低级鼠标钩子（WH_MOUSE_LL）。右键或
「检索选中文字」热键触发时，它模拟一次 Ctrl+C 把当前选区送进剪贴板，读出来，
再把剪贴板原样还回去——你在用的程序不会察觉内容被换过。

几个边界，都写在明面上：

- **探测不到就直说**：程序没响应 Ctrl+C、没选中文字、剪贴板里是图片或文件、
  选区超过 5000 字符——每一种失败都会在状态栏给出具体原因，不会静默。
- **剪贴板先备份后恢复**：探测前后用剪贴板序号核对，你原有的复制内容不会被弄丢。
- **排除列表**：终端这类把 Ctrl+C 当中断信号的程序默认被排除，列表可在设置里改。
- **钩子断了会自愈**：低级钩子可能被系统或其它程序悄悄摘掉，CiteDock 每两秒做一次
  健康检查，发现失活就自动重装；钩子的消息泵用阻塞等待实现，不会拖慢全系统的鼠标。
- **可随时关**：设置里关掉即彻底卸载钩子。

## 自检

```bat
:: 用你自己那个装了 PySide6 的 Python
set PY=python

%PY% tests\selftest_core.py     :: 建索引/检索/越界拦截/只读/源文件未被改
%PY% tests\selftest_i18n.py     :: 多语言守卫：漏翻、模块级 t()、往返切换
%PY% run.py --selftest          :: 窗口 + 托盘 + 热键 + 设置面板构建
%PY% run.py --smoke             :: 走真实启动路径跑 1.2 秒后退出
%PY% tests\shot.py %TEMP%\citedock_shots dark
```

> ⚠️ `run.py --selftest` 与 `--smoke` **默认读写真实的配置与索引库**
>   
> （`%LOCALAPPDATA%\CiteDock\`）。跑它们时建议先设
>   
> `set CITEDOCK_HOME=%TEMP%\citedock_agent`，避免动到你正在用的那份。
>   
> `tests/` 下的脚本会自己设 `CITEDOCK_HOME`，不用管。

## 已知边界

- 只索引文本类文件；`.xlsx/.xls` 仅索引文件名（表格正文需要额外加 openpyxl 并扩展取文器）。
- PDF 只取前 40 页文本；扫描件（图片型 PDF）取不到内容，只会命中文件名。
- 单文件索引上限默认 2 MB（可在设置里调），超出部分截断。
- 全局热键若被别的程序占用会注册失败，托盘会提示，可在设置里换组合。
- 隐藏目录（`.` 开头）和符号链接一律不索引。
- 本工具只做检索与引用整理，不做跨项目入口。

### 2026-10-14 · 项目一 21 条逻辑问题全部处理完

A 组 5 条决策 + T1~T9 九个任务全部落地，回归全绿。

对使用者的可见变化：

| 变化               | 说明                                                                           |
| ---------------- | ---------------------------------------------------------------------------- |
| **超限不再静默截断**     | 「复制内容」超出上限会**取消并点名**是哪几个文件放不下（旧版是悄悄丢掉后面的文件）；超大文件、正文被截断、取文失败三类**分别计数**并在状态栏显示 |
| **结果会自己验真**      | 渲染前逐项检查文件是否还在；不在的标红并写明"文件已不存在，建议重建索引"                                        |
| **看得出来为什么命中**    | 结果行上会标「文件名命中」「正文仅索引前半段」等标签                                                   |
| **取词更好用**        | 取词直接走宽松检索（关键词是从一段话里猜的，不该用 AND 卡死）                                            |
| **索引库能自愈**       | 右键菜单或设置面板里有「重建索引库」——把旧库改名成带时间戳的备份再重建，不删任何东西，也不碰源文件                           |
| **失效的检索范围会被标红**  | 旧版是静默忽略，用户以为还在索引                                                             |
| **搜索有结果会自动展开面板** | 旧版收起后搜到东西却看不见（这是个真 bug）                                                      |
| **排序修正**         | 文件名命中现在真的优先（旧版被 FTS5 隐藏列抢了排序，权重静默失效）                                         |

安全上多了一条：`_output` 被列为**保留目录名**，扫描器无条件排除，设置面板也不许把它加进检索范围 ——  
防止产物被自己索引、再被当成输入重新处理。
